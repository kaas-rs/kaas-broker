# Helm chart & deployment

**Book:** `docs/src/operations/helm.md`, `docs/src/operations/helm-values.md`, `docs/src/operations/storage.md`, `docs/src/operations/crds.md`. Read them for the design, and update them in the same commit when behaviour here changes.

`deploy/helm/kaas/` is the source of truth for production config (replicas, controller-Lease tuning, storage class, image repos). The chart bundles its CRDs in `crds/` (auto-generated by `cargo xtask gen-crds`). Helm intentionally does not upgrade CRDs across releases — see the chart's `README.md` for the upgrade procedure.

**Listeners are a Strimzi-shape array (gh #126).** `.Values.listeners` is `[]listener` where each entry has its own `name` (free-form), `port`, `type` (`internal` / `external`), `tls`, `authentication.type`, and an optional `enabled` flag (absence = enabled — `external`, `authed` and `oauth` ship as `enabled: false` defaults). Templates iterate this array to emit (a) the StatefulSet containerPorts + `KAAS_LISTENERS` JSON env, (b) headless + ClusterIP Service ports, (c) the NOTES.txt bootstrap-host output. **The KafkaCluster CR template still synthesizes the legacy single-listener shape** via `kaas.firstByType` for backwards-compat with the operator — a follow-up will refactor the operator side to consume the array natively.

**Internal TLS certificates come from a chart CA, and clients trust the CA (gh #343).** `templates/tls-internal.yaml`: a self-signed Issuer signs `<fullname>-internal-ca` (`isCA`, 10 years, `rotationPolicy: Never`), whose `ca` Issuer signs `<fullname>-broker-internal-tls`. Clients trust that Secret's `ca.crt`. Keep `rotationPolicy: Never` on the CA: cert-manager's default has been `Always` since v1.18, and a CA renewal with a new key breaks every client. Issuing the broker certificate straight from the self-signed Issuer, as the chart did before, makes every 75-day renewal a client outage. `cargo xtask check-chart` fails on either. A shell `kubectl get certificate` resolves to a Crossplane azuread CRD on the live cluster, so name `certificates.cert-manager.io` in full.

Cluster-wide authorization lives at `.Values.authorization.{type,superUsers}` (top-level, not nested under any listener). `type: ""` (default) leaves authorization off; `type: simple` enables ACL enforcement. `superUsers` (list of `User:foo` strings) is emitted as `KAAS_SUPER_USERS` and wraps whatever authorizer the broker picked in the super-user early-allow layer.

**Storage substrate**: the chart accepts `storage.accessMode: ReadWriteOnce` + a local-path class for single-broker deployments (the k3s overlay does this — RWX-NFS was the source of perf-bench DeadlineExceeded errors during saturation tests). Multi-broker requires `ReadWriteMany` with NFSv4-class semantics (same-directory rename atomicity, fsync durability, close-to-open consistency); see NOTES.txt for the provider matrix.
