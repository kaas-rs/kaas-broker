# kaas-auth

**Book:** `docs/src/architecture/listeners-auth.md`, `docs/src/compat/api/auth.md`, `docs/src/compat/api/acls-quotas.md`, `docs/src/code-tour/kaas-auth.md`. Read them for the design, and update them in the same commit when behaviour here changes.

SCRAM-SHA-512 and SASL PLAIN; there is no SCRAM-SHA-256. Credentials and ACLs load from `/data/__cluster/credentials.json` and `acls.json` (written by the operator) with hot-reload. Toggle off with `KAAS_AUTH_DISABLED=true`.

## Listeners, authentication, authorization (gh #124, #125, #126)

Three orthogonal axes, Strimzi 1:1:

- **`type`**: `internal` (in-cluster only) vs `external` (Gateway + cert-manager + per-broker hostnames). One listener per axis combination is normal — keep `plain` anonymous for in-cluster bench/UI traffic and add an `authed` SCRAM listener side-by-side.
- **`tls`**: `false` / `true`. `mtls` authentication implies `tls: true`; everything else is independent.
- **`authentication.type`**: `none` / `scram-sha-512` / `mtls` / `plain` / `oauth`. Each listener gets its own auth engine selected per listener name (`crates/kaas-auth/src/`). Anonymous listeners use an allow-all engine (no SASL handshake, no principal); authenticated listeners pre-gate connections in `crates/kaas-protocol/src/dispatch.rs` so a client must finish SASL before any non-handshake API is dispatched. **`oauth` = SASL/OAUTHBEARER (gh #42, KIP-255)**: JWTs validated locally against the issuer's JWKS (`crates/kaas-auth/src/oauth.rs`; fetch loop `spawn_jwks_refreshers` in `bins/kaas/src/main.rs`; Strimzi's `KafkaListenerAuthenticationOAuth` field names verbatim through `KAAS_LISTENERS`). Fail-closed before the first JWKS fetch; `alg` allowlist RS256/384/512+ES256; OAUTHBEARER (like PLAIN) refused over non-TLS; mechanism advertisement is per-listener (`AuthEngine::mechanisms`); KIP-368 partial — `maxSecondsWithoutReauthentication` advertises `session_lifetime_ms = min(cfg, token exp)` and the dispatcher answers 58 past the deadline, re-auth must keep the same principal. `KAAS_REQUIRE_SASL` (chart `auth.requireSasl`, gh #251 — re-port of the Go gate, dead config from the cutover until then) hands anonymous listeners the real engine too, so the pre-auth gate arms cluster-wide; `KAAS_AUTH_DISABLED=true` outranks it. SCRAM credentials rotate over the wire via keys 50/51 (KIP-554, gh #252): describe answers from the hot-reloaded credential store, alter derives RFC 5802 keys from the wire's salted material and patches `KafkaUser.spec.authentication.scram` (deletions and SCRAM-SHA-256 are refused with explicit errors — the CR owns the credential lifecycle).

**Authentication is per-listener; authorization is cluster-wide.** That split lives in `crates/kaas-auth/src/`:

- Authorizer — wired via `KAAS_AUTHORIZATION_TYPE` (`""` = none → allow-all; `simple` = ACL-based). `KAAS_SUPER_USERS` (comma-separated `User:foo,User:bar`) wraps the chosen authorizer in a super-user early-allow layer.
- Quota checker — real token buckets on every listener unless `KAAS_AUTH_DISABLED=true` swaps in a no-op. Quotas fire **regardless of authorization** — they're orthogonal.
- **ACL implication is Apache's** (`AclEngine::evaluate`, gh #268): an Allow on `Read`/`Write`/`Delete`/`Alter` also grants `Describe`, and `AlterConfigs` grants `DescribeConfigs`; Deny rules match only their exact op. Load-bearing: Metadata, ListOffsets, FindCoordinator, OffsetFetch, DescribeGroups and ListGroups check `Describe`, and a Strimzi consumer usually holds only `Read` on its group. Every handler checks the group/topic ACL **before** coordinator routing or existence lookups (an unauthorized principal must get 29/30, never `NOT_COORDINATOR` or `UNKNOWN_TOPIC_OR_PARTITION`), and all-topics Metadata / ListGroups / OffsetFetch **filter** instead of erroring. **A filter checks through `Authorizer::authorize_quietly`, never `authorize`** — the filter and the authorized-operations bitfield neither log nor count `kaas.acl.deny` (Apache's `logIfDenied = false`); a canary allowed 1 of 9 topics logged 8 WARNs per 30 s metadata refresh until they did. The engine reports a denial once per cache window, and only a reporting check marks it reported, so a quiet check that cached the denial first can't swallow a named request's audit line. Deny-path tests live in `crates/kaas-broker/tests/discovery_and_group_authz.rs`; its `Audited` wrapper fails any filter that reports.

Produce/Fetch handlers route exclusively via the cluster-wide authorizer + quota checker — they don't reach back into the per-listener engine. This is what lets `plain` (anonymous) and `authed` (SCRAM) listeners share the same ACL/quota policy.

**Per-listener Metadata advertisement (gh #125)**: each broker endpoint carries a per-listener port map; the Metadata handler looks up the port matching the request's listener so a client that bootstrapped on :9095 gets back :9095 in the Metadata response, not :9092. Without this, an authed-listener client got routed back to the anonymous listener and looped on SCRAM retry. The listener name on the connection is propagated via `crates/kaas-protocol/src/connstate.rs` (free-form string — no predefined constants; the chart picks the names).

**Quota debt-carry (gh #125)**: the token bucket (`crates/kaas-auth/src/quota.rs`) carries negative balances forward as debt instead of clamping at 0. With clamping, N concurrent clients each saw a "full" bucket and burst at N×rate before throttle kicked in (the 16-vs-10 MiB/s gap observed under bench-perf). Removing the clamp matches KIP-13. Test: `multi_client_contention_carries_debt` in `quota.rs`.

**mTLS principal mapping (gh #43, KIP-371)**: `crates/kaas-auth/src/principal_mapping.rs` parses Apache's `ssl.principal.mapping.rules` syntax — regex against the full subject DN with `$1`/`$2` back-references and optional `/L` / `/U` postfix flags; first matching rule wins, `DEFAULT` returns the CN. Wired on the server (`crates/kaas-protocol/src/server.rs`); the mTLS handshake path applies the mapper to the full subject DN before authenticating. Parse errors bubble at startup so chart-config typos fail fast rather than silently mapping every cert to the CN.
